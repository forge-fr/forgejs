## Step 01: Project Setup, Strict TypeScript & Node Runtime

*Create the workspace and start the server cleanly with @forge-fr/node*

- **Estimated time**: 5 min
- **Packages**: @forge-fr/cli, @forge-fr/node, @forge-fr/http
- **Module files**: `package.json`, `tsconfig.json`, `server.ts`
- **Playground verification tab**: https://github.com/forge-fr/forgejs/playground?tab=source

Every ForgeJS backend uses modern JavaScript modules (ESM) and strict TypeScript settings from day one so type mistakes are caught before deployment.

Your entry file connects createNodeAdapter() directly to createHttpApp() and wires attachProcessShutdown() so open requests and background jobs finish safely when the server stops.

### Key Architectural Highlights

- Uses modern ESM ("type": "module") with strict TypeScript compiler checks.
- createNodeAdapter({ trustHostHeader: true }) runs directly on native Node.js HTTP and WebSockets with no extra server wrapper.
- attachProcessShutdown(app, { exitOnComplete: true }) ensures active requests and queued jobs drain cleanly on SIGINT or SIGTERM.

### Implementation Code

**1. Bootstrap CLI (`terminal`)**

```bash
# Configure GitHub Packages registry for @forge-fr/*
echo "@forge-fr:registry=https://npm.pkg.github.com" >> .npmrc

# Create a modular backend workspace
npx @forge-fr/cli new task-webhook-api --template modular --runtime node
cd task-webhook-api

# Install ForgeJS domain, security, cache, queue, storage, and OpenAPI packages
npm install @forge-fr/core @forge-fr/http @forge-fr/node @forge-fr/validation \
  @forge-fr/auth @forge-fr/authorization @forge-fr/security \
  @forge-fr/cache @forge-fr/queue @forge-fr/storage \
  @forge-fr/logger @forge-fr/openapi zod @opentelemetry/api
```

**2. Node Runtime Entry (`server.ts`)**

```ts
import { attachProcessShutdown, createNodeAdapter } from '@forge-fr/node';
import { createPlaygroundBackend } from './src/playground-server/app.ts';

const PORT = Number(process.env['PORT'] ?? 3000);
const HOST = '0.0.0.0';

async function startServer(): Promise<void> {
  const backend = createPlaygroundBackend({
    adapter: createNodeAdapter({
      trustHostHeader: true,
    }),
  });

  await backend.start();

  const address = await backend.app.listen({ host: HOST, port: PORT });
  console.log(`ForgeJS backend listening on ${address.url}`);

  attachProcessShutdown(backend.app, {
    exitOnComplete: true,
    onShutdown: async () => {
      await backend.close();
    },
  });
}

void startServer();
```

## Step 02: App Kernel, Typed Tokens & Feature Modules

*Group each backend feature into a clean module with defineModule()*

- **Estimated time**: 8 min
- **Packages**: @forge-fr/core, @forge-fr/http
- **Module files**: `src/playground-server/app.ts`, `src/playground-server/types.ts`
- **Playground verification tab**: https://github.com/forge-fr/forgejs/playground?tab=source

As an API grows, putting all routes in one file quickly turns into messy cross-imports. The Playground backend uses ForgeJS feature modules: each folder owns its module setup, service logic, and HTTP routes.

Modules talk to each other only through typed tokens (createToken<T>()) and explicit exports, keeping boundaries clear and easy to test.

### Key Architectural Highlights

- No class decorators or reflection magic — createToken<T>() keeps full TypeScript type checking.
- Plugins (cache, queue, storage) boot in dependency order and shut down in exact reverse order.
- Global middleware adds request IDs, OpenTelemetry tracing, security headers, and rate limits across every route.

### Implementation Code

**app.ts Composition Root (`src/playground-server/app.ts`)**

```ts
import { createHttpApp } from '@forge-fr/http';
import { createCachePlugin } from '@forge-fr/cache';
import { createQueuePlugin } from '@forge-fr/queue';
import { createStoragePlugin } from '@forge-fr/storage';
import { createRateLimitMiddleware, createSecurityHeadersMiddleware } from '@forge-fr/security';
import { authModule } from './auth/auth.module.ts';
import { tasksModule } from './tasks/tasks.module.ts';
import { webhooksModule } from './webhooks/webhooks.module.ts';
import { attachmentsModule } from './attachments/attachments.module.ts';

const app = createHttpApp({
  logger,
  providers: [
    { token: PlaygroundStoreToken, useValue: store },
    { token: ObservabilityServiceToken, useValue: observability },
  ],
  modules: [
    authModule,
    securityModule,
    realtimeModule,
    webhooksModule,
    tasksModule,
    attachmentsModule,
    systemModule,
  ],
  plugins: [
    createCachePlugin({ adapter: cache }),
    createQueuePlugin({ queue, worker, drainTimeoutMs: 2_000 }),
    createStoragePlugin({ adapter: storage }),
  ],
});

app.use(createSecurityHeadersMiddleware({ contentTypeOptions: 'nosniff', frameOptions: 'SAMEORIGIN' }));
app.use(createRateLimitMiddleware({ max: 300, windowMs: 60_000 }));
```

**Feature Module Contract (`src/playground-server/tasks/tasks.module.ts`)**

```ts
import { defineModule } from '@forge-fr/core';
import { CacheTokens } from '@forge-fr/cache';
import { StorageTokens } from '@forge-fr/storage';
import { authModule } from '../auth/auth.module.ts';
import { AuthServiceToken } from '../auth/auth.service.ts';
import { webhooksModule } from '../webhooks/webhooks.module.ts';
import { WebhooksServiceToken } from '../webhooks/webhooks.service.ts';
import { PlaygroundStoreToken } from '../store.ts';
import { TasksServiceToken, createTasksService } from './tasks.service.ts';

export const tasksModule = defineModule({
  name: 'tasks',
  imports: [authModule, webhooksModule],
  providers: [
    {
      token: TasksServiceToken,
      scope: 'singleton',
      useFactory: (resolver) =>
        createTasksService({
          store: resolver.resolve(PlaygroundStoreToken),
          cache: resolver.resolve(CacheTokens.Adapter),
          storage: resolver.resolve(StorageTokens.Adapter),
          auth: resolver.resolve(AuthServiceToken),
          webhooks: resolver.resolve(WebhooksServiceToken),
        }),
    },
  ],
  exports: [TasksServiceToken],
});
```

## Step 03: Multi-Tenant Data Store & Predictable Seed Data

*Keep every workspace separated by tenantId with ready-to-test sample accounts*

- **Estimated time**: 6 min
- **Packages**: @forge-fr/core
- **Module files**: `src/playground-server/types.ts`, `src/playground-server/store.ts`
- **Playground verification tab**: https://github.com/forge-fr/forgejs/playground?tab=tasks

In a multi-tenant SaaS app, every record belongs to a workspace (tenantId). Putting tenantId right on your TypeScript types and store methods makes sure queries never mix data between customers.

During startup, the Playground store hashes demo passwords securely and adds starter files so you can test every feature right away or reset the sandbox with one click.

### Key Architectural Highlights

- Separate TypeScript types keep internal fields like passwordHash away from public user responses.
- Two separate demo companies (Acme Corp and Globex Labs) let you test tenant isolation immediately.
- In production, you can swap the in-memory store token for @forge-fr/database, @forge-fr/drizzle, or @forge-fr/prisma without changing your routes.

## Step 04: Login Methods, Roles & Tenant Access Rules

*Support passwords, JWTs, HttpOnly cookies, scoped API keys, OAuth2 PKCE, and ownership checks*

- **Estimated time**: 10 min
- **Packages**: @forge-fr/auth, @forge-fr/authorization
- **Module files**: `src/playground-server/auth/auth.module.ts`, `src/playground-server/auth/auth.service.ts`, `src/playground-server/auth/auth.middleware.ts`, `src/playground-server/auth/auth.controller.ts`
- **Playground verification tab**: https://github.com/forge-fr/forgejs/playground?tab=auth_lab

Real backends often need more than one login method: browser apps use HttpOnly cookies or Bearer JWTs, CLI tools use scoped API keys, and social/SSO logins use OAuth2 PKCE.

@forge-fr/auth handles strong Argon2id password hashing, JWT verification, hashed sessions, API keys, and OAuth2 PKCE, while @forge-fr/authorization checks roles, record ownership, and tenant isolation.

### Key Architectural Highlights

- createPasswordHasher() uses safe Argon2id defaults and constant-time checks.
- Scoped API keys limit access strictly (for example, allowing tasks:read while blocking deletes).
- assertTenantIsolation() and ownership rules block cross-tenant snooping (IDOR) automatically.

### Implementation Code

**Auth & Policy Engine (`src/playground-server/auth/auth.service.ts`)**

```ts
import {
  createJwtService,
  createPasswordHasher,
  createSessionManager,
  createApiKeyService,
  createOAuth2Client,
} from '@forge-fr/auth';
import {
  assertTenantIsolation,
  createAuthorizer,
} from '@forge-fr/authorization';

const passwordHasher = createPasswordHasher();
const jwtService = createJwtService({
  algorithm: 'HS256',
  secret: process.env['JWT_SECRET'] ?? 'dev-secret-change-in-prod',
  issuer: 'forgejs-playground',
  audience: 'forgejs-api',
});

const authorizer = createAuthorizer({
```

## Step 08: Background Webhooks, Retries & Dead-Letter Replay

*Send outbound webhooks asynchronously with automatic retries and easy recovery*

- **Estimated time**: 9 min
- **Packages**: @forge-fr/queue, @forge-fr/security
- **Module files**: `src/playground-server/webhooks/webhooks.module.ts`, `src/playground-server/webhooks/webhooks.service.ts`, `src/playground-server/webhooks/webhooks.controller.ts`
- **Playground verification tab**: https://github.com/forge-fr/forgejs/playground?tab=webhooks

API writes should return quickly instead of waiting on slow third-party webhook servers. Here the webhooks service queues jobs so createQueueWorker() can deliver them in the background.

If delivery fails, the worker retries automatically. Jobs that fail every attempt move into the Dead-Letter Queue (DLQ), where admins can inspect and replay them later.

### Key Architectural Highlights

- createQueueWorker() provides clear callbacks: onCompleted, onFailed, and onDeadLetter.
- Admin permission checks and SSRF URL guards stop unauthorized users or unsafe targets from registering webhooks.
- Admins can replay dead-letter jobs from the API (with an optional healthy-sink override in the sandbox).

### Implementation Code

**Queue & Worker Setup (`src/playground-server/app.ts`)**

```ts
import { createMemoryQueueAdapter, createQueueWorker } from '@forge-fr/queue';

const queue = createMemoryQueueAdapter({
  maxQueueSize: 500,
  defaultMaxAttempts: 2,
  defaultBackoff: { type: 'fixed', delayMs: 60 },
});

const worker = createQueueWorker(
  queue,
  async (job, execCtx) => {
    const payload = job.payload as WebhookJobPayload;
    if (payload.targetUrl === 'sandbox://sink/fail') {
      throw new Error('502 Bad Gateway from failing sink');
    }
    if (payload.targetUrl === 'sandbox://sink/flaky' && execCtx.attempt === 1) {
      throw new Error('503 Service Unavailable on attempt 1');
    }
    return { delivered: true, statusCode: 200 };
  },
  {
    pollIntervalMs: 20,
    concurrency: 4,
    onCompleted: (job) => store.updateDeliveryByJobId(job.id, { status: 'delivered', statusCode: 200 }),
    onFailed: (job, err) => store.updateDeliveryByJobId(job.id, { status: 'retrying', lastError: String(err) }),
    onDeadLetter: (job, err) => store.updateDeliveryByJobId(job.id, { status: 'dlq', lastError: String(err) }),
  },
);
```

# Introduction

> What ForgeJS is, how it stays simple and portable across runtimes, and how it compares with Express, Fastify, Hono, and NestJS.

- **Section**: Getting Started
- **Packages**: @forge-fr/core, @forge-fr/http
- **Version**: v1.0.0
- **Updated**: 2026-11-27
- **HTML URL**: https://github.com/forge-fr/forgejs/docs/getting-started/introduction
- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/getting-started/introduction.md
- **Source**: https://github.com/forge-fr/forgejs/blob/main/docs/quick-start.md

## What is ForgeJS?

ForgeJS is an open-source TypeScript backend framework built on standard web APIs (Request, Response, Headers, Streams, and Web Crypto) using modern JavaScript modules (ESM).

Instead of locking your business logic to one server runtime or relying on complex class decorators, ForgeJS separates your app code from the server layer across 21 focused @forge-fr/* packages synchronized at v1.0.0.

- 16 of the 21 packages have zero third-party runtime dependencies, keeping installs small and predictable.
- Tested locally on Node.js v22.23.5 and Bun 1.4.4, plus an edge runtime adapter (@forge-fr/edge) for Cloudflare Workers and Deno.
- 63 automated boundary checks verify that core framework packages never accidentally import Node-only or Bun-only APIs.

## Design philosophy & framework comparison

ForgeJS favors clear, explicit wiring over hidden framework magic. You pass typed service tokens (createToken<T>()), group features into modules (defineModule()), and extend the app with permission-checked plugins (definePlugin()) while keeping startup and request speed fast.

| Area | ForgeJS Approach | Trade-off to Keep in Mind |
| --- | --- | --- |
| Modules & Wiring | Plain typed tokens & defineModule() functions | No class decorators or reflect-metadata needed |
| Runtime Portability | Standard Web API core + small Node, Bun, and Edge adapters | Modern ESM only (Node.js >= 22.18.0; no CommonJS require) |
| Security Posture | Safe HTTP defaults + ready-to-use OWASP ASVS 5.0.0 security middleware | Your app services still decide who owns each record |
| Database Support | Official PostgreSQL, Drizzle, and Prisma plugins with UnitOfWork | TypeORM, MikroORM, Sequelize, and Knex are not built-in |

## When ForgeJS might not be the right fit

- Your project still depends on CommonJS require() or runs on Node.js older than 22.18.0.
- Your team specifically wants decorator-based class controllers (like NestJS) or built-in TypeORM/MikroORM.
- You only need a tiny single-file router and do not want lifecycle management, modules, or built-in security helpers.

# Your First Application

> Step-by-step backend app combining createKernel(), defineModule(), validatedHandler(), security headers, and clean shutdown.

- **Section**: Getting Started
- **Packages**: @forge-fr/core, @forge-fr/http, @forge-fr/validation, @forge-fr/security, @forge-fr/node
- **Version**: v1.0.0
- **Updated**: 2026-11-27

- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/getting-started/first-application.md

## Complete modular service example

This complete service keeps its data store private inside a module, shares a typed service token, adds security headers, validates both incoming requests and outgoing responses, and shuts down cleanly on SIGTERM.

**File: `src/app.ts`**

```ts
import { createKernel, createToken, defineModule } from '@forge-fr/core';
import { createHttpApp } from '@forge-fr/http';
import { createNodeAdapter, attachProcessShutdown } from '@forge-fr/node';
import { createSecurityHeadersMiddleware } from '@forge-fr/security';
import { validatedHandler } from '@forge-fr/validation';
import { z } from 'zod';

interface ProjectRecord {
  id: string;
  name: string;
  ownerId: string;
}

interface ProjectService {
  create(name: string, ownerId: string): ProjectRecord;
  list(): ProjectRecord[];
}

const ProjectServiceToken = createToken<ProjectService>('ProjectService');

const ProjectsModule = defineModule({
  name: 'projects',
  providers: [
    {
      token: ProjectServiceToken,
      scope: 'singleton',
      useFactory: () => {
        const records: ProjectRecord[] = [];
        return {
          create(name, ownerId) {
            const item = { id: crypto.randomUUID(), name, ownerId };
            records.push(item);
            return item;
          },
          list: () => [...records],
        };
      },
    },
  ],
  exports: [ProjectServiceToken],
});

const kernel = createKernel({ modules: [ProjectsModule] });
await kernel.start();

const app = createHttpApp({ container: kernel.container });
app.use(createSecurityHeadersMiddleware());

app.get('/api/projects', async (ctx) => {
  const projects = await ctx.container!.resolve(ProjectServiceToken);
  return ctx.json({ items: projects.list() });
});

app.post(
  '/api/projects',
  validatedHandler(
    {
      body: z.object({
        name: z.string().min(2).max(80),
        ownerId: z.string().min(1),
      }),
      response: z.object({
        id: z.string().uuid(),
        name: z.string(),
      }),
    },
    async (ctx, input) => {
      const projects = await ctx.container!.resolve(ProjectServiceToken);
      const created = projects.create(input.body.name, input.body.ownerId);
      // ownerId is automatically stripped by the response schema
      return ctx.json({ id: created.id, name: created.name }, { status: 201 });
    },
  ),
);

const server = await app.listen(createNodeAdapter(), { host: '127.0.0.1', port: 3000 });
attachProcessShutdown(server, { onShutdown: () => kernel.shutdown() });
```

# Architecture

> How ForgeJS organizes code into 6 clear layers enforced by 60 automated boundary checks across all 20 packages.

- **Section**: Core Concepts
- **Packages**: @forge-fr/core, @forge-fr/router, @forge-fr/http
- **Version**: v1.0.0
- **Updated**: 2026-11-27

- **Source**: https://github.com/forge-fr/forgejs/blob/main/docs/architecture.md

## Six clear layers that depend in one direction

ForgeJS keeps your business logic separate from server runtimes and database drivers. Outer layers depend on inner contracts, never the other way around.

| Layer | Packages | Role & Boundary Rule |
| --- | --- | --- |
| Application | Your controllers + @forge-fr/http + @forge-fr/validation | Turns HTTP and WebSocket requests into typed calls to your services |
| Domain | Your defineModule() services + @forge-fr/authorization | Pure business logic; never imports Node or Bun globals |
| Infrastructure | database, drizzle, prisma, auth, security, logger, cache, queue, storage | Connects external tools through permission-checked plugins |
| Framework Core | @forge-fr/core, @forge-fr/router, @forge-fr/http | Zero third-party dependencies; built only on standard Web APIs |
| Runtime Adapters | @forge-fr/node, @forge-fr/bun, @forge-fr/edge, @forge-fr/testing | Connects the app to Node.js, Bun, Edge workers, or in-memory tests |

## Automated boundary checks

The test suite runs 60 automated checks across all 20 packages to confirm there are no forbidden runtime globals (like node:* or Bun) in core packages, no circular package dependencies, and valid ESM exports.

> **NOTE: Why keeping @forge-fr/core runtime-free matters**
>
> Because @forge-fr/core, @forge-fr/router, @forge-fr/http, and @forge-fr/validation rely strictly on Web Standards, your exact same app logic and middleware run on Node.js 22, Bun 1.4, and Cloudflare Workers without extra polyfills.

# Application Lifecycle

> Predictable 7-stage startup and shutdown lifecycle in ApplicationKernel with automatic rollback on boot errors.

- **Section**: Core Concepts
- **Packages**: @forge-fr/core
- **Version**: v1.0.0
- **Updated**: 2026-11-27
- **HTML URL**: https://github.com/forge-fr/forgejs/docs/concepts/lifecycle
- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/concepts/lifecycle.md
- **Source**: https://github.com/forge-fr/forgejs/blob/main/docs/architecture.md

## Seven predictable stages from boot to shutdown

| Stage | State Transition | What Happens |
| --- | --- | --- |
| configure | created → configuring → configured | Validates app and plugin settings using your config schemas |
| register | configured → registering → registered | Registers module and plugin services into the DI container |
| initialize | registered → initializing → initialized | Runs module and plugin setup hooks in dependency order |
| start | initialized → starting → started | Opens database pools, starts queue workers, and prepares servers |
| ready | started → ready | App is live, accepting requests, and passing /health/ready |
| shutdown | ready → shutting_down → shutdown | Finishes active requests and stops plugins in reverse order |
| dispose | shutdown → disposing → disposed | Runs cleanup callbacks (last-in, first-out) and frees resources |

## Watching lifecycle events & automatic boot rollback

Listen to kernel.events.on("lifecycle:stage") or register hooks with kernel.hooks.add(). If a plugin fails while starting, ApplicationKernel automatically cleans up everything that already started in reverse order before throwing the error.

**File: `src/kernel.ts`**

```ts
import { createKernel } from '@forge-fr/core';

const kernel = createKernel();

kernel.events.on('lifecycle:stage', ({ from, to }) => {
  console.info('Kernel transition:', from, '->', to);
});

kernel.hooks.add('ready', async () => {
  console.info('All modules and plugins are ready');
});

await kernel.start();
await kernel.shutdown();
```

# Configuration & Secrets

## Typed configuration manager

createConfigManager() combines defaults, environment values, and optional schema validation while blocking unsafe key paths like __proto__, constructor, and prototype.

**File: `src/config.ts`**

```ts
import { createConfigManager, secret, type SecretValue } from '@forge-fr/core';

interface AppConfig {
  readonly port: number;
  readonly databaseUrl: SecretValue<string>;
}

const config = createConfigManager<AppConfig>({
  defaults: {
    port: 3000,
    databaseUrl: secret('postgres://localhost:5432/dev'),
  },
  values: {
    port: Number(process.env.PORT ?? 3000),
    databaseUrl: secret(process.env.DATABASE_URL ?? 'postgres://localhost:5432/dev'),
  },
});

const port = config.get<number>('port');
const dbSecret = config.get<SecretValue<string>>('databaseUrl');
// dbSecret.toString() === '[REDACTED]'
// Call dbSecret.reveal() only right where the database client needs it
```

## How SecretValue protects credentials

- Anything wrapped in secret() prints as "[REDACTED]" in JSON.stringify(), toString(), valueOf(), and console inspection.
- You explicitly call .reveal() only when handing a credential to a database, JWT signer, or S3 client.
- redactObject() scans nested objects and masks sensitive fields before logging or reporting.

# Dependency Injection

> Wire services cleanly with typed tokens, singleton/transient/request lifetimes, cycle detection, and automatic cleanup.

- **Section**: Core Concepts
- **Packages**: @forge-fr/core, @forge-fr/testing
- **Version**: v1.0.0
- **Updated**: 2026-11-27
- **HTML URL**: https://github.com/forge-fr/forgejs/docs/concepts/dependency-injection
- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/concepts/dependency-injection.md
- **Source**: https://github.com/forge-fr/forgejs/blob/main/docs/architecture.md

## Typed tokens and service lifetimes

- singleton — Created once for the whole app and cleaned up automatically when the app stops.
- transient — Created brand new every time resolve() is called.
- request — Created once per HTTP request (via container.createScope()) and cleaned up as soon as that request finishes.

**File: `src/di.ts`**

```ts
import assert from 'node:assert/strict';
import { createContainer, createToken } from '@forge-fr/core';

const ConfigToken = createToken<{ appName: string }>('app.config');
const RequestIdToken = createToken<string>('request.id');

let seq = 0;
const container = createContainer();

container.register({
  token: ConfigToken,
  scope: 'singleton',
  useValue: { appName: 'forge-orders' },
});

container.register({
  token: RequestIdToken,
  scope: 'request',
  useFactory: () => `req-${++seq}`,
});

const scope = container.createScope();
assert.equal(scope.resolve(RequestIdToken), 'req-1');
assert.equal(scope.resolve(RequestIdToken), 'req-1');
assert.equal(scope.resolve(ConfigToken).appName, 'forge-orders');
await scope.dispose();
await container.dispose();
```

## Built-in safety checks for wiring mistakes

| Error Class | When ForgeJS Throws It |
| --- | --- |
| ScopeViolationError | A long-lived singleton tries to depend on a per-request service |
| CircularDependencyError | Service A depends on B and B depends back on A (prints the exact loop) |
| ProviderNotFoundError | You ask for a token that was never registered or exported |
| ContainerDisposedError | You try to register or resolve a service after the app shut down |

# Encapsulated Modules

> Organize features with defineModule(), keep internal helpers private by default, and share only explicit exports.

- **Section**: Core Concepts
- **Packages**: @forge-fr/core
- **Version**: v1.0.0
- **Updated**: 2026-11-27
- **HTML URL**: https://github.com/forge-fr/forgejs/docs/concepts/modules
- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/concepts/modules.md
- **Source**: https://github.com/forge-fr/forgejs/blob/main/docs/architecture.md

## Private by default, shared only when exported

Services registered inside defineModule() stay private to that module unless you list their tokens in exports. If another module tries to access a private token, ForgeJS stops immediately with ProviderNotVisibleError.

**File: `src/modules/billing.module.ts`**

```ts
import { createKernel, createToken, defineModule } from '@forge-fr/core';

const RepoToken = createToken<{ count(): number }>('BillingRepo');
export const BillingServiceToken = createToken<{ total(): number }>('BillingService');

export const BillingModule = defineModule({
  name: 'billing',
  providers: [
    { token: RepoToken, scope: 'singleton', useValue: { count: () => 12 } },
    {
      token: BillingServiceToken,
      scope: 'singleton',
      inject: [RepoToken] as const,
      useFactory: (repo) => ({ total: () => repo.count() * 100 }),
    },
  ],
  exports: [BillingServiceToken],
});

const kernel = createKernel({ modules: [BillingModule] });
await kernel.start();
const billing = kernel.container.resolve(BillingServiceToken);
console.info('Total cents:', billing.total());
```

## Shared module deduplication & loop protection

- If two different modules both import the same SharedModule, ForgeJS registers and initializes SharedModule only once.
- Circular module imports fail right at startup with CircularModuleDependencyError before any code runs.

# Request & Response

## Size-limited body readers & response helpers

- Built-in body readers (JSON, text, bytes, form URL-encoded, and multipart) enforce a 1 MiB default limit even when clients omit Content-Length.

## Predictable execution order & safety guards

- Middleware always runs in a clear order: global → module → group → route (with optional numeric priority inside each level).
- Calling next() twice throws ForgeMiddlewareError, and trying to change headers after a response is sent throws ResponseCommittedError.
- ForgeJS compiles and caches each route pipeline once, avoiding extra per-request overhead.

## Seven HTTP lifecycle hooks

| Hook | When It Runs | Common Use Case |
| --- | --- | --- |
| onRequest | Before route matching | Start request timers or tracing spans |

| preSerialization | After your handler returns data, before JSON encoding | Wrap response payloads or audit fields |
| onSend | Right before the final Response is returned | Attach custom response headers |
| onError | Whenever a middleware or handler throws | Log structured errors with ctx.requestId |
| onResponse | After the response is finished | Record access logs and latency metrics |

## Register the PostgreSQL plugin & run transactions

Add createPostgresPlugin() and its config to createKernel({ plugins }). It automatically registers a readiness health check and closes the connection pool cleanly when the app stops.

**File: `src/db/postgres.ts`**

```ts
import { createKernel, secret } from '@forge-fr/core';
import {
  createPostgresPlugin,
  DefaultDatabaseTokens,
  runInTransaction,
} from '@forge-fr/database';

const kernel = createKernel({
  plugins: [
    [
      createPostgresPlugin(),
      {
        url: secret(process.env.DATABASE_URL ?? ''),
        max: 20,
      },
    ],
  ],
});

await kernel.start();
const adapter = kernel.container.resolve(DefaultDatabaseTokens.adapter);

await runInTransaction(
  adapter,
  async (tx) => {
    await tx`INSERT INTO audit_events (event_type) VALUES (${'boot'})`;
  },
  { isolationLevel: 'read committed' },
);
```

```ts
import { createToken, defineModule } from '@forge-fr/core';

          return { id, totalCents: 4200 };
```

## Passwords, JWTs, and hashed sessions

- createArgon2PasswordHasher() enforces OWASP Argon2id strength settings and works seamlessly across Node.js (@node-rs/argon2) and Bun (Bun.password).
- createJwtService() requires an explicit list of allowed algorithms, blocks alg: none, and requires at least 32-byte HMAC secrets.
- Session tokens and API keys are stored only as SHA-256 hashes and compared in constant time to prevent timing attacks.

**File: `src/auth.ts`**

```ts
import { secret } from '@forge-fr/core';
import {
  createArgon2PasswordHasher,
  createJwtService,
  createMemorySessionStore,
  createSessionManager,
} from '@forge-fr/auth';

const hasher = createArgon2PasswordHasher();
const hash = await hasher.hash('CorrectHorseBattery99!');
const valid = await hasher.verify('CorrectHorseBattery99!', hash);

const jwt = createJwtService({
  algorithms: ['HS256'],
  secret: secret('super-secret-signing-key-at-least-32-bytes'),
  issuer: 'https://auth.example.com',
  audience: 'forge-api',
});
const token = await jwt.sign({ sub: 'user-1', role: 'editor' }, { expiresIn: '10m' });

const sessions = createSessionManager({
  store: createMemorySessionStore(),
  idleTtlMs: 30 * 60_000,
  absoluteTtlMs: 24 * 60 * 60_000,
});
```

## Roles, custom rules & multi-tenant boundaries

createAuthorizer() evaluates roles, explicit denials, custom attribute rules, and tenant matching consistently in both HTTP routes and domain services via authorizer.forActor(actor). Any deny rule always wins over allow.

**File: `src/authz.ts`**

```ts
import {
  assertOwnership,
  createAuthorizer,
  definePolicy,
} from '@forge-fr/authorization';

const authorizer = createAuthorizer({
  enforceTenantIsolation: true,
  roles: {
    viewer: { permissions: ['invoice:read'] },
    billingAdmin: {
      inherits: ['viewer'],
      permissions: ['invoice:*'],
      deniedPermissions: ['invoice:delete'],
    },
  },
  policies: [
    definePolicy({
      name: 'deny-suspended-actor',
      effect: 'deny',
      actions: ['*'],
      condition: ({ actor }) => actor.attributes?.['suspended'] === true,
    }),
  ],
});

const billing = authorizer.forActor({
  subject: 'u-10',
  tenantId: 'tenant-a',
  roles: ['billingAdmin'],
  permissions: [],
  scopes: [],
});

const decision = await billing.evaluate('invoice:update', { tenantId: 'tenant-a' });
assertOwnership(billing.actor, { ownerId: 'u-10' });
```

# Plugin System

> How ForgeJS plugins check version compatibility, boot in dependency order, detect conflicts, and run with scoped permissions.

- **Section**: Plugins & Extensions

## Declared permissions & locked PluginContext

Every plugin lists the exact capabilities it needs. At startup, ForgeJS hands the plugin a locked context object that only lets it call the APIs it declared.

| Capability | What the Plugin Is Allowed to Do |
| --- | --- |
| di:register | Register private or exported services into the DI container |
| di:resolve | Read exported services from core or declared plugin dependencies |
| config:read | Read settings from ConfigManager |
| events:emit | Send typed kernel events |
| events:listen | Listen to kernel lifecycle or app events |
| hooks:register | Attach callbacks to kernel lifecycle hooks |
| health:register | Add liveness or readiness checks to HealthRegistry |

## Version checks, boot order & conflict protection

- forgeVersion ranges are checked against the running @forge-fr/core version before any plugin runs.
- Plugins start in dependency order and shut down in exact reverse order.
- If a plugin calls an API it did not declare, ForgeJS stops immediately with PluginCapabilityError.
- Conflicting plugins or circular dependencies fail fast at startup with clear error messages.

## Writing a plugin with definePlugin()

Use definePlugin() to declare your plugin capabilities, supported ForgeJS version range, and a configSchema so bad settings are caught right at startup.

**File: `src/plugins/metrics.plugin.ts`**

```ts
import { createToken, definePlugin, FORGE_CORE_VERSION } from '@forge-fr/core';
import { z } from 'zod';

export interface MetricsClient {
  increment(metric: string): void;
}

export const MetricsToken = createToken<MetricsClient>('acme:metrics');

export const metricsPlugin = definePlugin({
  name: 'acme-metrics',
  version: '1.0.0',
  forgeVersion: `^${FORGE_CORE_VERSION}`,
  capabilities: ['di:register', 'health:register'],
  configSchema: z.object({
    namespace: z.string().min(1).default('app'),
  }),
  register(ctx, config) {
    ctx.registerProvider({
      token: MetricsToken,
      scope: 'singleton',
      useValue: {
        increment: (metric) => console.info(`[${config.namespace}] ${metric}`),
      },
    });
    ctx.registerHealthCheck('acme-metrics', () => ({ status: 'up' }));
  },
});
```

## Test plugins in isolation with createPluginTestHarness()

createPluginTestHarness({ plugin, config }) starts a real kernel with just your plugin so you can test its exported tokens, health checks, and cleanup hooks easily.

**File: `tests/metrics.plugin.test.ts`**

```ts
import assert from 'node:assert/strict';
import { createToken, definePlugin } from '@forge-fr/core';
import { createPluginTestHarness } from '@forge-fr/testing';
import { z } from 'zod';

const MetricsPortToken = createToken<number>('metrics.port');

const MetricsPlugin = definePlugin({
  name: 'metrics-plugin',
  version: '1.0.0',
  forgeVersion: '^1.0.0-rc.1',
  capabilities: ['di:register', 'health:register'],
  configSchema: z.object({ port: z.number().int().min(1024).default(9090) }),
  register(ctx, config) {
    ctx.registerProvider({ token: MetricsPortToken, useValue: config.port }, { export: true });
    ctx.registerHealthCheck('metrics', () => ({ status: 'ok' }));
  },
});

const harness = createPluginTestHarness({
  plugin: MetricsPlugin,
  config: { port: 9100 },
});

await harness.start();
assert.equal(harness.resolveExport(MetricsPortToken), 9100);
assert.equal((await harness.health()).status, 'ok');
await harness.shutdown();
```

## Prevent duplicate loads & clear cache by tag

If many requests miss the same cache key at the exact same moment, getOrSet() runs your loader function once and shares the result with all waiting callers, protecting your database from traffic spikes.

**File: `src/cache.ts`**

```ts
import assert from 'node:assert/strict';
import { createMemoryCacheAdapter } from '@forge-fr/cache';

const cache = createMemoryCacheAdapter({ maxEntries: 2_000 });
let loads = 0;

const [a, b] = await Promise.all([
  cache.getOrSet('profile:42', async () => {
    loads += 1;
    return { id: '42', tier: 'pro' };
  }, { ttlMs: 60_000, tags: ['user:42'] }),
  cache.getOrSet('profile:42', async () => {
    loads += 1;
    return { id: '42', tier: 'pro' };
  }, { ttlMs: 60_000, tags: ['user:42'] }),
```

```ts
  async (job, ctx) => {
```

| Error Strategy | What Happens If a Listener Throws |
| --- | --- |

# Frequently Asked Questions

> Straight answers on runtime support, database ORMs, typed tokens vs. decorators, security boundaries, and benchmarks.

- **Section**: Community & Contributing
- **Packages**: @forge-fr/core, @forge-fr/http
- **Version**: v1.0.0
- **Updated**: 2026-11-27
- **HTML URL**: https://github.com/forge-fr/forgejs/docs/community/faq
- **Markdown URL**: https://github.com/forge-fr/forgejs/docs/community/faq.md
- **Source**: https://github.com/forge-fr/forgejs/blob/main/FRAMEWORK_FEATURE_INVENTORY.md

## Why does ForgeJS use typed tokens instead of decorators?

Plain createToken<T>() and defineModule() keep TypeScript types accurate without experimental decorator metadata or extra runtime reflection, which also keeps cold startups fast across Node.js, Bun, and Edge.

## Which databases and ORMs are officially supported?

ForgeJS ships official plugins and UnitOfWork adapters for PostgreSQL (@forge-fr/database via postgres-js), Drizzle ORM (@forge-fr/drizzle), and Prisma ORM (@forge-fr/prisma). You can still connect other ORMs or SQL databases via DatabaseAdapter.

## Where can I install v1.0.0 packages?

All 21 packages are published at v1.0.0 under the @forge-fr/* scope on public npm (https://registry.npmjs.org) and mirrored on GitHub Packages (https://npm.pkg.github.com) from https://github.com/forge-fr/forgejs.

## Does ForgeJS make my app automatically secure?

No framework can guarantee full app security on its own. ForgeJS ships safe HTTP defaults and OWASP ASVS 5.0.0 building blocks, while your team still handles ownership and tenant checks in services, HTTPS/TLS, secret management, and WAF/DDoS protection.
